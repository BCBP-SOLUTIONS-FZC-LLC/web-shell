# Changelog

All notable changes to this shell are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning aligned with SemVer.

`0.1.0` is the first release. Everything before it is in its section below. `package.json` `version` matches the latest tag without the `v`. This file tracks what is true in each release and what is still outstanding. The development diary, when one is needed, is `git log`.

**Format (as the platform's services keep theirs).** Under `[Unreleased]`, each change sits in a section typed and dated with its topic, newest first (in the order the pull requests merged): `### Added|Changed|Fixed|Removed|Security (YYYY-MM-DD — topic)`. Each entry is a bold one-line summary, then what changed and why, with the files, tests and checks that prove it; a behaviour change ends with *(Previously: …)*. `### Known gaps` and `### Current architecture notes` at the end of `[Unreleased]` say what is true and outstanding on `main` now; while `[Unreleased]` is empty, those at the end of the latest release section do. Cutting a release turns `[Unreleased]` into `## [X.Y.Z] - YYYY-MM-DD` (`release.yml` needs that heading).

Pull requests that change the shell, its dependencies, or the image add an entry under `[Unreleased]`. `.github/workflows/changelog-check.yml` fails a pull request that touches `src/`, `package.json`, `package-lock.json`, `Dockerfile`, `nginx/`, `rsbuild.config.ts`, `config/**`, `public/config/**`, or `index.html` without updating this file. `.github/workflows/release.yml` rejects a tag that has no matching `## [X.Y.Z]` section (`verify-changelog-entry.sh` looks for the version without the `v`).

## [Unreleased]

### Fixed (2026-11-26 — one theme for every remote)

**The theme a user picks now follows them into every remote and across reloads.** Every remote draws with `html[data-theme]`, but only mfe-dashboard set it (from its own storage), so mfe-admin and the others showed the default after a reload or when opened first. The shell now puts its saved theme on the page before a remote mounts and saves whatever theme a remote sets, in `storage('shell')` (new key `…:shell:theme`, cleared on sign-out and workspace switch; `src/infrastructure/storage/sharedTheme.ts`). Remotes change nothing. Not breaking for remotes or environments.

### Changed (2026-11-26 — the frame becomes a sidebar)

**The shell's frame is a sidebar beside the page, as in the product's reference design, instead of a header across the top.** `AppSidebar` (`src/presentation/widgets/AppSidebar.tsx`, replacing `AppHeader`) is dark: an icon rail beside a panel of labels, each row's icon in the rail and its label in the panel, the current item highlighted in both. Top: the workspace (an initial, P-1's name and the slug), a button that opens Switch workspace under it. Then links with icons (inline SVG, `src/presentation/components/Icons.tsx`) to Dashboard, Tenders, Drafting and Workflows, and Admin in its own group. Bottom: My account, the user (initial, name, email), Sign out, and Collapse sidebar, which folds the panel to the rail on a wide screen (labels kept as the links' names and their tooltips, which show only while it is collapsed beside the page). The choice is saved per workspace on this device in the SDK's `storage('shell')` (new key `…:shell:sidebarCollapsed`; `SidebarPreferenceRepository`, `src/infrastructure/storage/sidebarPreference.ts`), cleared on sign-out and workspace switch. Colours `#0c0c0e`, `#161618`, `#27272a` with text `#fafafa`, `#d4d4d8`, `#a1a1aa`: all WCAG AA. On a wide screen (1024 px and up) it is `sticky` at the window's full height and the page is the rest of a `flex` row. On a narrow one it is a modal drawer under a bar at the top ("Open menu" / "Close menu", which stays in view): focus moves into it, the page behind it is `inert`, Escape anywhere, a link, Close menu or the dimmed page closes it and focus returns to the menu button, and while closed its links are out of the tab order. The new-version notice now heads the page column, sticky under the bar, instead of being fixed across the top, so it covers neither the sidebar nor the bar. Everything else is as before: which links show, Admin's permission, links followed without a page load, Switch workspace and its failure text, Sign out, flag `shell.frame`.

**Remote contract: `--shell-sidebar-width` is new (additive), and `--shell-header-height` changes meaning: it now measures the narrow-screen bar.** `--shell-sidebar-width` is the sidebar's width while it is beside the page and `0px` while it is a drawer. `--shell-header-height` is `0px` on a wide screen (previously the header's height there). A remote's fixed elements start at `left: var(--shell-sidebar-width, 0px)` and `top: var(--shell-header-height, 0px)`. No remote reads either yet. Catalogue: `app.frame.sidebar`, `app.frame.openMenu`, `app.frame.closeMenu`, `app.frame.collapse`, `app.frame.expand` added; `app.frame.userMenu` and `app.frame.workspace` removed (106 keys).

Tests: `test/integration/bootstrap.test.tsx` (App gets the SDK storage), `test/integration/app.test.tsx` (the modal drawer's focus, the page inert, closing on a wide screen, the workspace and user, the drawer and its toggle, collapsing to the rail, Switch workspace closing, icons and the Admin group, the published sizes), `test/e2e/shell.test.tsx` (sidebar links, Sign out and Switch workspace with the real SDK), `test/unit/workspace-status.test.ts` (the saved choice, per workspace), `test/browser/shell.spec.ts` (at a desktop width beside the page with `--shell-sidebar-width` equal to its width and AA contrast, collapsed to the 64 px rail, and still collapsed after a reload; at a phone width the modal drawer, Close menu and Escape; the new-version notice clear of the sidebar and the bar; at a phone width a drawer; mouse clicks in three engines). *(Previously: a header across the top with an "Account menu" holding My account, Switch workspace and Sign out.)*

### Fixed (2026-11-26 — "Sign in" after a sign-out opens the login page)

**"Sign in" on the "You are signed out" screen now opens the shell's login page (work email, workspace name or link) instead of redirecting straight to Keycloak.** The screen reused the remembered workspace and went to the identity provider with no input from the user. ### Current architecture notes

- A static browser app: the production process is nginx on 8080 (uid 101). No backend, database or message bus in this repository.
- `src/` follows the Frontend Architecture Constitution's folders (`app/`, `presentation/`, `application/`, `domain/`, `infrastructure/`, `shared/`); `eslint.config.js` and `npm run arch-lint` enforce the layers in CI.
- Only `PLATFORM_ENVIRONMENT` (a fallback now) and `BUILD_VERSION` are compiled in. Everything else is `/config/runtime.json`, validated strictly by the SDK.
- The shell draws a sidebar (the workspace, section links, Admin, My account, Sign out) beside every remote; remotes are to draw only their own section navigation (mfe-tender and mfe-dashboard still draw their own frames, LLD §15 #23).
- Every user-facing word is a key of the SDK `/i18n` `shell` namespace (`src/shared/i18n/en.json`), loaded before the first screen.
- The access token goes only to the page's own origin, by the SDK's `ApiClient`; the browser never sends identity headers. Tokens are never stored.
- Error boundaries: `RemoteBoundary` for `dashboard`, `tenders`, `drafting`, `workflows`, `admin` and `me`, `MFEErrorBoundary` (`web-shell`) for the shell's own routes.
- Coverage is gated at 95% (100% today). `COVERAGE_THRESHOLD` can override the gate locally; no workflow sets it.
- Claude Code: `.claude/settings.json` hooks, the `invariant-reviewer` and `doc-sync-reviewer` subagents, the `/sdk-upgrade` and `/stack-sync` skills.

### Changed (2026-11-25 — SDK `1.0.0-alpha.10`: a remote's session-context refresh)

**All three platform packages move to `1.0.0-alpha.10`, exact, on one version, and the shell value gets `refreshContext`, so a remote can reload IAM P-35 without a page load** (web-shell's session-context refresh handoff, for mfe-admin; LLD §15 #25 closed). A remote calls the SDK's `useRefreshSessionContext()` after the user changed their own roles, or after a `403 DENY_ROLE_INSUFFICIENT`. The shell's `refreshContext` runs the focus refresh's load (`reloadContext` in `src/app/bootstrap/bootstrap.tsx`) at once, not held to the focus refresh's minute, and resolves `true` when a new context was applied while it ran, by its own load or by one it waited for (a focus refresh, a newer background-retry answer), so a remote is not told nothing changed when its change is live; `false` when nothing new was applied, its own load failed (the context is kept; a step that throws after the load is logged as `session context refresh failed`), or the shell took over the page (a refusal's screen, the wrong-workspace screen, after a sign-out or an expiry). Never rejects. One load runs at a time: a focus while one runs is skipped, and a remote's call waits for a running load, then loads afresh, because that one may have read P-35 before the change; every load restarts the focus refresh's minute. Where the SDK's reference shell applies a context with a new slug for the same tenant, this shell keeps its stricter rule and shows the wrong-workspace screen. The release also brings `<Writable>` and the written `navigate()` contract, which need nothing from the shell. Shell before remotes: a remote that calls the hook or uses `<Writable>` must be built on alpha.10, so it needs this shell; under an older shell the hook resolves `false`. Checks: `npm run test-contract` against mfe-dashboard `v0.4.0` (alpha.6) passes 12/12; no new SDK export duplicates a shell name. Tests: `test/integration/bootstrap.test.tsx` (12 cases: applied, unchanged and failed, refused, another workspace, after a sign-out, waiting for a focus refresh, `true` when a focus refresh it waited for applied the change, `true` when a newer background-retry answer did, never rejecting when a step after the load throws, a focus skipped during its load, two calls in turn, a sign-out while waiting), `test/e2e/shell.test.tsx` (a remote's `useRefreshSessionContext()` with the real SDK). *(Previously: a remote could not ask; a change showed on the next focus after a minute, or a reload.)*

### Fixed (2026-11-25 — a remote's navigate() into the remote already showing)

**A remote's `navigate()` to another path in the remote already showing now opens that path, not only the URL** (shared-components-and-navigation handoff §3.3, option a; the handoff is kept outside this repository). Each remote runs its own router, which does not see the shell's navigation: the SDK's `navigate('admin', '/t/acme/admin/users')` while `/admin/settings` showed changed the address bar and left the page. `RouterBridge` in `src/app/routes/App.tsx` now hands the SDK a navigate that remounts the routes (the same `key` the header's links use) when the target's section, its first segment, is the one the shell's routes show and the move changed the address bar's path or query, so the remote's router starts at the new URL. A move to another section mounts that remote anyway; a move that changes nothing (the same path and query, or a hash) remounts nothing, so a remote's state is kept and a remote that navigates to where it is cannot loop. Sections are compared as the routes match them: decoded and without case. Within its own section a remote should use its own router, query changes (filters, tabs) included, or it is remounted and loses its state. Once the app is gone (a sign-out, a refusal screen), a late `navigate()` does nothing, so the screen that replaced the app stays and no page load can start a sign-in without a click. No preset change, no shared router. The remote contract (LLD §4.5) now states the `navigate()` rules: the path decides (`appId` is ignored), a cross-remote path carries the workspace prefix. Tests: `test/integration/app.test.tsx` (same section remounts, another section mounts once, the section the shell shows when a remote's own router moved the address bar, no remount for a move that changes nothing, sections compared decoded and without case, nothing done once the app is gone, `sectionOf`), `test/e2e/shell.test.tsx` (the real SDK `navigate()` within `admin`, then into `me`, no page load), `test/browser/shell.spec.ts` (the dashboard follows its own `navigate()` in three engines under the production CSP). *(Previously: only the header's links remounted the section; a remote's own `navigate()` within its section changed the URL alone, LLD §15 #18.)*

### Added (2026-11-25 — the session-context refresh on focus)

**The page asks IAM P-35 again when it gets focus, at most once a minute, so a role or plan change made elsewhere reaches the remotes without a reload** (mfe-admin's session-context handoff, the shell-only part). Roles are not in the token (IAM-UX-2): a user promoted or demoted by another admin kept the old hints until a reload. On `focus` or the tab becoming visible, `CONTEXT_REFRESH_MS` (60 s) after the last ask, the bootstrap loads P-35 once (`loadSessionContextOnce`, no retries) and applies a changed context as the background retry does (subject, flags, `rememberWorkspace`, banners once, router); the same context changes nothing. A workspace state (A6/A8, access paused) is settled as on the first load and replaces the app with its screen (after an expiry it unmounts the app under "Session ended", as the background retry does); a context for another workspace shows the wrong-workspace screen (`isPageWorkspace` in `src/domain/rules/workspaceAccess.ts`: a trial with a slug needs that slug, as on the first load; otherwise the same tenant as the page's context, and the same slug when both name one, so a body without a slug or with `null` keeps its context); any other failure logs `session context refresh failed` and keeps the context. A deny-all page recovers its permissions this way too. Nothing runs after a sign-out, an expiry or a refusal screen. The background retry now shares the apply and refuse steps (`takeContext`, `refuseApp` in `src/app/bootstrap/bootstrap.tsx`), and ends once a refresh has applied a context or a refusal has replaced the app (its own abort signal). Every P-35 request after the first load is numbered, and an answer is applied only if no later request's answer has been, so an older read never undoes a newer one, whichever of the two answers last (platform-reactcommon's review of the refresh handoff). Tests: `test/unit/session-context.test.ts` (`isPageWorkspace`), `test/integration/bootstrap.test.tsx` (26 cases), `test/e2e/shell.test.tsx` (a role given elsewhere reaches the remote on focus). *(Previously: P-35 was loaded once per page, plus the background retry after a transient failure.)*

### Added

### Known gaps

- **Official help and legal URLs.** Privacy Policy, Terms of Service, Trust & Security and "Trouble logging in?" are hidden until their URLs are set in `src/pages/links.ts`; none is published on bcbpsolutions.com yet.

- **The IAM endpoints are stubbed locally only.** PUB-1 and P-35 must exist behind `/api` in every real environment. Without P-35 the shell renders with deny-all permissions, logs a warning, and retries a transient failure three times in the background.

- **The shipped runtime config is a default.** `public/config/runtime.json` uses the SDK defaults (`https://auth.bcbpsolutions.com`, client `tender-web`). Each environment serves its own `/config/runtime.json` and `/remotes/manifest.json` (CloudFront, or a file mounted over the image's). The image's manifest is `{}`, so the dashboard slot is empty until one is provided.

- **The CSP comes from CloudFront.** The image sends none by default. CloudFront's policy (`platform-reactcommon/examples/cloudfront`) must include the IdP origin in `form-action` for the global sign-out. An environment without CloudFront mounts `nginx/security.d/csp.conf.example`.

- **`mfe-dashboard` is still on alpha.3.** Until it is rebuilt with the alpha.4 preset, this shell cannot load it, locally or deployed.

- **Essential telemetry only (v1 decision).** `src/platform/consent.ts` grants `essential` only: errors and essential warnings are exported; traces, metrics and info logs are not, until a consent manager is added.

- **No cluster deploy.** `release.yml` publishes the image and the GitHub Release. Nothing in this repo applies a Helm chart or rolls a deployment. An operator rolls the new tag and serves that environment's `/config/runtime.json` and `/remotes/manifest.json`.

- **Pre-v1.** Per SemVer, a `v0.x` tag would not promise compatibility across minor bumps. No tag exists yet. The contract table in [VERSIONING.md](./VERSIONING.md) is what a future `v1.0.0` would freeze.

### Current architecture notes

- This is a static browser app. The production process is nginx. There is no Go service, database, or message bus in this repository.
- Only `PLATFORM_ENVIRONMENT` and `BUILD_VERSION` are compiled in (`__ENVIRONMENT__`, `__BUILD_VERSION__`). Everything else is read from `/config/runtime.json` at start-up and validated strictly by the SDK; an unknown key or an invalid value stops the app with the "unavailable" message.
- The access token is sent only to the page's own origin (`/api`), by the SDK's `ApiClient`. Identity headers are never sent from the browser.
- Port **8080** is Keycloak in the local compose file and the listen port of the shell image. Run the image with a different host port when both are up.
- Coverage is enforced in CI and is not lowered for this repo. `COVERAGE_THRESHOLD` can override `.github/scripts/coverage-gate.mjs` locally. The workflow does not set it.
- `CODEOWNERS` requests review from `@BCBP-SOLUTIONS-FZC-LLC/web-shell`, including workflow files, the Dockerfile, and `nginx/`.
